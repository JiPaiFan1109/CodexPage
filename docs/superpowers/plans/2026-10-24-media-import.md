# Wallpaper Engine 媒体兼容扩展实施记录

> 使用 executing-plans 在当前会话逐项实施，采用测试驱动验证。用户已批准上一轮给出的分层方案并要求直接执行。

**目标：** 兼容媒体继续直引，不兼容视频和动图自动转换，扩展静态图片支持，给场景提供明确标注的静态预览降级，并记录完整场景渲染的真实边界。

**架构：** PowerShell/WPF 保持不变，FFmpeg 作为独立 LGPL 共享构建子进程，使用 Windows Media Foundation H.264 编码。运行时不联网下载。构建时按固定版本与 SHA256 准备工具，保留上游许可及源码信息。转换缓存与源文件身份关联，不与用户本地副本合并；源消失后隐藏并停用，非使用中旧缓存可回收。

**约束：** 只改 current，保留现有未发布改动；根 Git 为旧源码，不能由其 HEAD 建立新开发基线。不安装、不发布、不启动 Wallpaper Engine、不重启 Codex。目标输出沿用 1080p/30fps、静音 H.264、128MiB 上限。超限失败而不截断。场景/网页仅导入明确标注的 project.preview，不执行脚本/EXE、不把素材当完整场景。无预览则说明跳过原因。

## Review focus

1. 中文、空格和 shell 字符文件名必须作为原样参数传入子进程。
2. 源文件删除/替换不能继续把转换缓存当有效壁纸。
3. 活跃视频不可被自动清理；用户本地副本不跟随 Steam 删除。
4. 损坏文件、工具缺失和超限不能留下半成品或阻止其余项目导入。
5. 场景预览不能悄悄成为“完整动态支持”，也不能执行不可信网页/程序。
