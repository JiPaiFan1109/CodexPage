# 桌面 Codex 启动失败兜底（未发布）

开发 VERSION/package.json 仍为 3.4.0。本修复尚未打包、发布或安装，不属于已公开的 3.4.0 附件。

## 现场事实与结论边界

用户报告：安装 CodexPage 3.4.0 后，通过桌面快捷方式打开 Codex 完全无窗口；重启系统、结束后台任务后仍失败。卸载后打开 Codex，再安装 CodexPage 后恢复。尚无该用户故障日志、进程快照或原快捷方式文件。“完全无窗口”不等于没有后台进程。

附件仅提出配置切换、旧进程交接、Codex 自身更新等可能性，不能作为根因证据。

源码确认：launch-entries.ps1 将匹配的普通 Codex 入口指向 CodexPage 启动器，卸载恢复未被用户修改的已接管入口。旧 Start-DynamicFullLauncher 启动隐藏子进程后立即返回，不观察失败。完整脚本虽对 CDP 启动失败已有原生回退，但模块导入、操作锁、Node 校验及部分状态/主题检查失败不在该内部回退范围。因此壁纸前置失败可能阻塞桌面 Codex 入口，卸载恢复入口能绕过该路径。

此软件缺陷已复现，与现场描述吻合；尚不能确认现场具体失败点、是否为 3.4.0 独有回归或官方配置损坏。重装恢复也可能涉及后台停止、原生配置初始化、临时占用解除或商店更新完成，现有资料无法区分。

## 修改与来源

仅修改 engine/scripts/launch-dream-skin.ps1 的普通快捷方式慢速路径：

- 保留子进程句柄并观察退出码，成功和用户取消（退出码 0）保持原行为。
- 子进程启动失败、非零退出或日志目录不可用时，尝试原生激活。
- 重新发现当前用户已验证的官方商店安装，不依赖 state.json、Node、主题、独立 profile 或壁纸操作锁，不传 CDP/profile 参数，不通过被接管的快捷方式启动。
- 任一已注册 Codex 版本仍有进程时保留会话，不结束进程或另开默认 profile；避免重复完整脚本已有的回退。
- 日志记录原始失败及 native-activation-requested、existing-codex-preserved 或 native-fallback-failed。激活请求成功不等于窗口已验证可见。

优先复用项目现有开源实现及 Windows 包激活接口。来源/许可见 SOURCE_PROVENANCE.md、THIRD_PARTY_NOTICES.md、LICENSE：Codex-Dream-Skin v1.5.18，MIT。无新增依赖、框架或安装成本。
