## 结构与关键流程

| 模块 | 作用与审查内容 |
| --- | --- |
| `scripts/skin-manager.ps1`、`.xaml`，`manager-launcher.cs` | WPF 管理器、后台工作线程、选择/分页/确认/预览/连接/更新状态；入口去重、忙碌保护、错误与关闭处理 |
| `wallpaper-library.ps1`、`wallpaper-engine.ps1`、`media*.ps1` | 本地副本、Steam 直引/转换缓存、路径与媒体校验、按库互斥、原子元数据、去重、应用前校验与回滚 |
| `engine/scripts/*windows.ps1`、`existing-session.ps1`、`multi-instance.ps1` | Store 身份检测、CDP 连接、启动/恢复、进程身份验证、多实例监测、更新入口锁 |
| `injector.mjs`、`renderer-inject.js`、`video-*.mjs` | 严格本机端点、主题和 Safe CSS 验证、Blob 传输与缓存、隐藏暂停、可见恢复、DOM 修复、监听器/定时器释放 |
| `app-update.ps1`、`finish-update.ps1`、`check-upgrade.ps1`、`installer/windows.iss` | 签名更新、下载大小/哈希与取消、缓存复验、进程交接、安装占用门禁与卸载恢复；本轮仅源码/模拟验证 |
| 构建与 CI | 固定 Node、许可证/哈希/签名校验、版本对齐、发行附件清单；没有运行完整构建、安装器或远端 CI |

主要流程为：导入先校验和暂存 → 库互斥内提交 → 用户应用时复验文件 → 备份当前配置 → 写入新配置并调用引擎 → 确认成功或回滚。Steam 兼容项先入库，转换按已有确认流程进行。视频由带随机令牌的 loopback 服务提供，经大小和 SHA256 验证后传入渲染器；隐藏页面暂停，恢复/替换时释放旧资源。更新下载与实际安装保持分离。

## 安全、兼容和维护审查结论

- 路径保护、库删除保护、进程 PID/路径/启动时间复核、更新签名/大小/哈希拒绝、恶意或损坏媒体、非法 CDP 端点和 Steam 源丢失由源码检查及现有回归覆盖。测试结果只支持这些具体边界，不代表全应用安全证明。
- 项目没有 npm 第三方依赖树；核心外部依赖为 Node、Windows PowerShell/WPF/Media Foundation、Inno Setup、按需获取的 FFmpeg 和 Codex 私有界面/CDP 行为。没有用空的 npm audit 代替二进制依赖审计，也没有完成全部二进制 CVE/供应链审计。
- 先调查了现有开源上游 [Codex Dream Skin](https://github.com/Fei-Away/Codex-Dream-Skin)：API 为 MIT、未归档、最后 push 为 2026-10-15。沿用现有 MIT 实现、Node 内置 HTTP/文件 API 和既有 WPF，不引入替代框架或新依赖。修复规模不足以证明迁移引擎/播放器/更新框架的收益，迁移还会增加进程、兼容与发行验证成本。
- FFmpeg 组件仍先验证归档 SHA256；缓存执行前主要核对结构与文件长度，不逐次哈希所有 DLL。其同账户篡改保护不是完整安全边界；本次没有证明可跨越新的信任边界，不将其包装成已确认漏洞。第三方解码器仍未沙箱化；stdout/stderr 的无界读取已在后续补查中复现并限制，详见补查记录，没有将组件桩输出洪泛等同于真实恶意媒体利用。
- 新增修复没有数据库/库格式迁移，没有移除功能，排序、筛选、导入确认、静音播放与重启确认习惯保留。仍未实现跨版本更新的完整事务回滚/断电恢复。
