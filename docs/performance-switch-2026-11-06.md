# 3.5.0 壁纸切换旧图片查找优化

本轮为未发布源码优化，VERSION/package.json 保持 3.5.0。未安装、打包、发布、重启生产 Codex 或修改真实壁纸库。保留此前图库、初始化和运行时探测优化。

## 问题与改动

`Set-DreamSkinActiveTheme` 在取得旧图片路径、供成功后的清理使用时，调用了完整图片元数据校验。旧图片不会在这一步被渲染或应用，解析结果也不参与新图片有效性判断。现改为调用已有的 `Read-DreamSkinTheme -SkipImageMetadata`，保留主题契约、目录包含、重解析点、文件存在性、格式/大小和外部源哈希检查。

新图片的源文件、临时副本、重命名副本和最终主题读取仍完整校验，每次运行 Node 前仍检查签名。不增加信任缓存，不更改状态刷新与删除前的完整状态校验，也不改动应用事务的备份和回滚。

这是一个局部收益：成功替换已有有效本地图片的 `Use-DynamicWallpaper` 路径，由 6 次元数据校验降至 5 次。首次应用没有有效旧图片时不一定有此收益。旧图片的内容损坏但其路径与契约仍有效时，成功替换后现在可清理该旧文件；外部图片仍不作为本地副本删除。

## 开源来源与依赖成本

先核对了 [Microsoft PerfView](https://github.com/microsoft/perfview) 及其 [MIT 许可证](https://github.com/microsoft/perfview/blob/main/LICENSE.TXT)。本轮只需要确定函数调用次数与阶段耗时，沿用项目的 .NET Stopwatch 和现有校验选项，无需安装完整分析器、引入第三方依赖或复制开源代码。若下一阶段需要跨线程 CPU/内存归因，可另行评估 PerfView。

## 测量方法与限制

脚本位于工作区 `.local-evidence/performance-switch-20261106/measure.ps1`。使用项目自带 PNG，真实导入和写入隔离目录；`Apply` 为无操作回调，未操作 Codex 或真实壁纸。运行时使用本机已安装的官方签名 Node，并保留每次签名检查。

先测独立 before/after，观察到明显预热/负载差异；这些数据保留，不能据此计算可信收益比例。随后在同一进程、同一隔离库中从快照提取旧函数，交替运行旧/新函数（AB、BA、AB），其他函数保持相同。计时包含本地应用准备与事务，不含真实引擎启动、CDP、GPU 显示；计时后的当前壁纸识别另行断言，不计入总耗时。元数据子阶段为非递归单层计时，可与总耗时比较。

原始每轮时间、实际校验路径、当前项识别断言存于证据目录下各 run 的 `results.json`。样本少，系统负载及签名验证缓存仍会造成波动；不能外推为固定百分比或端到端切换提升。

最终交替结果（毫秒）：

| 轮次 | 原实现 | 优化后 | 本轮少用时间 |
| --- | ---: | ---: | ---: |
| 1（原→新） | 10273.98 | 6542.65 | 3731.33 |
| 2（新→原） | 7405.27 | 6045.75 | 1359.51 |
| 3（原→新） | 7052.27 | 5753.48 | 1298.80 |

中位数为 7405.27→6045.75 ms，观测减少 18.36%。三轮均确认为 6→5 次元数据校验，且计时后的当前壁纸识别通过。第一轮收益明显更大，仍有预热影响，不宣称每次都节省 3.7 秒。独立前后序列分别还与部分回归测试重叠，不用于最终收益计算；最终交替序列不与本轮其他测试并行。

## 验证

新增 `tests/theme-switch-validation.tests.ps1`。改动前按预期失败（旧图片仍被解析），改动后通过：旧图不解析、新图四处校验、坏新图拒绝且不改主题、本地旧图清理、目录穿越与外部源保护。红/绿日志分别保留。

初次总回归进程在连续切换清理测试期间结束，未留下该测试的完成记录，原因未确认；空的中断日志保留为 `media-rollback-cleanup-interrupted.log`，不计为通过。恢复运行只跳过已有明确成功退出码的媒体和壁纸操作测试，未完成项重新执行。

只读独立复核未发现本次改动的可行动缺陷。相关媒体、切换、回滚清理及恢复回归与最终哈希结果以证据目录的最终验证文件为准。未做本轮 UI/GPU 或真实连接测速；界面未改动。此前偶发导入访问拒绝根因仍未知，本次改动不声称修复该问题。

最终 `final-verification.json` 通过：5 个 Windows 脚本（含新增红/绿测试）、57 项 Node 测试、183 个 PowerShell 解析。10 次连续切换后备份数量与保留字节均为 0；失败恢复证据保留、清理失败不重应用、取消/失败/正常恢复通过。核对前两轮修改哈希未被覆盖，产品差异仅为本轮单处调用及说明注释，版本未变。汇总校验工具初次遇到 PowerShell 5.1 JSON 数组枚举和 Node 默认 reporter 格式不匹配，修正工具后复验通过；原测试退出码和日志未改变。
