# 3.9.0：启动守卫与壁纸可靠性

日期：2026-11-21。基于 v3.8.0（`c5defd4`）的发行分支 `codex/release-3.9.0`，不含 4.0.0 的 MineCodex 部分。

## 解决的问题

此前，只要 Codex 不是从 CodexPage 的入口打开（任务栏、开始菜单应用列表、`codex://` 链接、开机恢复上次的应用、Codex 自动更新后自行重启），新进程就没有壁纸连接。后台监控会等 15 秒，再弹出置顶的“重新启动 Codex？”确认框。拒绝只对当前这个进程有效，所以开机后和每次 Codex 更新后都会再弹。维护者本机记录显示，Codex 在一个月内从 26.1013 更新到 26.1117，几乎每次更新都会触发一次弹窗。

调试端口只能在进程启动时打开。Codex 现在是 Chromium 外壳（`chrome.dll` 158），程序目录受签名保护，不能让它在其他入口自己带上端口。

## 做法

1. **启动守卫**（`engine/scripts/multi-instance.ps1`）：监控在等待间隙每 300 ms 枚举一次 `ChatGPT` 进程（不经过 WMI）。发现新进程后立即开始下一轮检查，判断它能否安全替换：
   - 没有暂停，有壁纸状态，并且属于记录中的 Codex 包系列；
   - 不是 CodexPage 自己在还原或启动失败后打开的（`native-launch.json` 标记前后 30 秒内）；
   - 10 分钟内的替换不超过 3 次；
   - 进程启动不超过 4 秒；或者窗口还没出现且不超过 20 秒；或者启动后没有任何键盘鼠标输入且不超过 90 秒；
   - 安装或更新没有占用 `.update-gate`。
   满足条件时，再次核对进程号、启动时间和程序路径，然后结束该进程及其子进程，接着以无确认方式启动带连接的 Codex。原命令行中的 `codex://` 链接会原样转交。其他情况一律不动，也不弹窗。
2. **去掉重启弹窗**：监控不再请求确认框。旧版监控遗留的 `-UpdateRecoveryKey` 调用直接退出，`update-recovery-notice.json` 会被清理。
3. **冷启动更快出现壁纸**（`injector.mjs`）：此前 watcher 只给新页面 1.8 秒，然后按 5、10、20、30 秒退避。现在，对新出现的 Codex 应用页面，会在已打开的连接上等待最多 20 秒，此后每 1.5 秒重试；新目标出错时最多退避 10 秒。同时移植了 4.0.0 分支中已验证的重载修复（TASK-114）：健康检查不健康时不再立即断开，60 秒内每 1.5 秒复查。
4. **随机端口**：每次新建连接实例使用 20000–59999 之间的随机空闲回环端口，不再固定 9345。`SECURITY.md` 补充了本地调试端点的风险说明。
5. **清理残留**：应用失败或取消后，旧背景恢复完成即删除回滚快照。监控每 6 小时清理一次超过 14 天的归档状态、快照和每次启动的日志，各保留最近若干份；只匹配本工具生成的文件名，不跟随链接。
6. **视频校验缓存**：视频服务启动时，如果同一文件（卷、文件 ID、大小、时间戳都相同）已经校验过，就不再整份重新计算 SHA-256。

## 验证

- Node 测试全部通过（新增视频校验缓存和早期脚本时限用例）。
- Windows 回归：见下方“全量结果”。新增 `launch-guard.tests.ps1`（判定规则、深链接、替换、进程号复用、包隔离、更新门、启动失败回退、弹窗移除、本机探测）和 `state-cleanup.tests.ps1`；更新 `host-update-recovery.tests.ps1` 与 `media-rollback-cleanup.tests.ps1`。
- 真实隔离 Codex（独立配置档和 Codex home，没有触碰维护者正在使用的 Codex）：
  - 守卫发现新进程平均约 0.4 秒；该 Codex 窗口约 8–11 秒后才出现；结束进程 0.3–0.6 秒，没有残留子进程。证据：`.local-evidence/release-3.9.0/evidence/guard-live-probe-result.json`。
  - 视频壁纸冷启动，从 Codex 界面出现到壁纸出现：旧版 3.9–9.2 秒，新版 5.2–6.4 秒。计时显示剩余时间主要用于等 Codex 页面空闲：页面刚出现时，一次探测排队约 3.7 秒，应用壁纸约 1 秒。证据：`coldstart-video-gap.json`。

## 限制

- 已经在使用中的、不带连接的 Codex 不会被替换，只能等下次打开，或在管理器中重新连接。安装 3.9.0 时如果 Codex 正在运行，这次会话不受影响。
- 完整的“守卫替换后启动带连接实例”链路，需要关闭维护者正在使用的 Codex 才能在本机实测，本轮没有执行。各环节已分别在隔离环境验证：发现、结束进程、带连接启动、注入。
- 本地调试端点对本机其他程序开放的风险仍然存在，随机端口不是访问控制。
- 未覆盖：注销/物理重启后的真实开机恢复、Codex 商店真实更新后的自行重启、多显示器和不同 DPI。
