# 动态缩略图、媒体顺序与默认壁纸

2026-11-09，开发版本仍为 3.6.0。这是未发布的源码修改，不等同于公开 v3.6.0 或本机 3.6.0 加 local-hash-module-patch 的安装。本轮没有覆盖本机安装、重启 Codex、应用真实壁纸或修改真实图库。

## 用户决定与实现

1. 视频卡片在当前可见图库内自动静音循环播放。保持原有圆角、遮罩、名称、选中标记与预览操作；加载前或解码失败保留静态缩略图。不可用项目不尝试播放。
2. 左下切换区改为左“图片”、右“视频”。按钮事件继续按媒体类型筛选，滑块目标改为 Image=0 / Video=108；默认混合且无滑块，再次点击同类型恢复混合。
3. 将用户截图中的星空、海边篝火、地球依次作为“默认1、默认2、默认3”。首次打开空图库时复制并校验内置文件，不自动应用壁纸。已有图库保持原样；默认内容改名或删除后不因重开而恢复。

用户确认“原创或已有再分发授权”，并明确选择不重新编码，仅 ZIP 无损压缩。三份 MP4 与指定本机原件逐字节哈希一致，共 176,990,002 字节（约 168.79 MiB），另有缩略图开销。没有裁剪、调分辨率、调帧率或重新编码。来源声明及六份文件的哈希见 `engine/assets/default-wallpapers/SOURCE.md`、`manifest.json`。这份声明不等于独立审查了原作者授权文件，媒体不自动适用代码 MIT 许可。

## 实现与成本

- 先查阅微软 [WPF-Samples](https://github.com/microsoft/WPF-Samples)（MIT，含 VideoViewerDemo）及 [MediaElement 文档](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/graphics-multimedia/how-to-control-a-mediaelement-play-pause-stop-volume-and-speed)。参考原生媒体生命周期，未复制第三方组件代码、未增加播放器依赖。
- 新增 `scripts/manager-thumbnails.cs`，由现有 PowerShell/WPF 初始化加载。使用 WPF MediaElement 和现有位图缩略图；每页仍最多 12 张卡片，不改变媒体排序或数据格式。
- 翻页/卸载卡片、图库进入专注预览、写入操作禁用图库、最小化或关闭窗口时释放媒体源；滚动离开视口时停止；回到可见区域重新打开。卡片复用时切换源，坏视频不会每个时钟周期重复打开。遵循 Windows ClientAreaAnimation 偏好，关闭系统界面动画时保留静态缩略图，大预览仍可手动打开。
- 启动加载阶段在后台 runspace 初始化默认图库。用既有图库互斥锁、路径检查、SHA256、暂存目录移动及原子状态写入，逐项记录完成状态。部分失败可重试；中断留下的默认暂存副本在重试时清理复用。已有项目不会被默认内容覆盖。
- `build-release.ps1` 显式纳入三组媒体及新增 C# 文件，并在准备包文件清单时校验媒体哈希。现有 ZIP Optimal、安装目录映射和安装文件清单会覆盖这些路径；没有改变发行标签、签名或已公开附件。
- 代价：ZIP 对 MP4 的压缩空间有限；未来实际包大小以构建结果为准。安装目录会保留内置原件，首次图库另有副本，仅三个视频合计占用约 337.58 MiB 的两份存储，不含安装包、临时文件和缩略图。动态图另有解码器/显存开销，不受既有 64 MiB 静态位图缓存估算预算约束。

## 修正过程与限制

保留初次测试日志：首次 C# 编译漏引 System.Xaml，随后补齐；新测试初始无 BOM 导致 Windows PowerShell 5.1 中文断言不一致，修正测试编码后通过。播放器初次以自身零尺寸判断可见性，无法启动，改用父卡片的几何范围；修正后播放进度实测通过。Loaded 是直接事件，最终通过 WPF 类事件处理器注册每张卡片。旧筛选位置断言更新；导入集成测试明确使用“用户已清空图库”夹具，首次默认图库有独立测试。

真实窗口的 UIA 初次读取超时，扩大单窗读取预算后正常；一次按名称查找预览按钮超时，重新观察后用新元素令牌点击成功。未退到前台输入、未抢占鼠标或键盘焦点。

本轮不是发行全套验收：未构建/签署/安装新发行包，未验证多显卡、多屏、全部解码器组合、12 路高分辨率视频长期播放或全天驻留。窗口完全被其他窗口遮挡不等同 WPF IsVisible=false，当前没有加入操作系统级遮挡检测。自然导入访问拒绝的既有根因问题不因此视为解决。正式发布仍须另定版本并对最终安装包做发行验证。
