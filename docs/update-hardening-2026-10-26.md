# 更新逻辑加固验收记录

完成日期：2026-10-27。修改位于 current，VERSION 与 package.json 保持 2.3.1，属于公开 2.3.1 之后的本地修改。未发布新版、未覆盖生产安装、未重启 Codex。

## 已实现

- 更新检查区分尝试与成功，失败采用退避重试；持续打开管理器也能再次检查。自动发现只提醒一次，不主动展开设置。
- 下载与安装分开：下载期间管理器可继续使用，支持取消；校验完成后由用户点击“立即安装”。按 SHA256 缓存最多两个安装包，复用仍校验签名、长度与哈希。
- 管理器和引擎入口持共享文件锁，安装器持独占文件锁，防止文件替换期间新入口启动；ZIP 安装也校验占用与降级。
- 安装进程持续监测，超过两分钟提示耗时并提供日志入口、允许最小化，不强杀安装器。安装器退出码分别解释。
- 安装成功须核对 installed-files.json 的路径、长度和哈希；启动管理器须收到随机令牌对应的窗口就绪信号。结果原子写入，启动失败保留安装包与诊断。
- 过期暂存清理限定归属、目录形态和活动租约，错误日志轮换；宿主恢复请求区分等待、确认和拒绝，过期待处理请求有限重试。
- 启动器版本由 VERSION 生成；构建阻止 package.json 版本不一致。统一更新测试纳入 CI。
- 发布脚本校验十个附件，允许中断后跳过已验证附件继续上传；缺远端摘要时下载校验。发布后网络失败可重跑只读验证，禁止覆盖公开附件。

具体行为见 app-updates.md。继续使用现有 Inno Setup，没有迁移更新框架。

## 边界与后续验收

1. 本轮未构建完整发行包。最小安装器夹具、隔离脚本测试不能代替下一正式候选包的完整安装、覆盖升级、卸载与库保留验收；远端 CI 未在本轮执行。
2. 尚未实现跨版本自动事务回滚或断电恢复。结果文件和互斥锁不等于完整事务恢复，涉及用户数据迁移时尤其如此。
3. 旧客户端仍使用它自身的更新助手与入口，因此从旧版升级的首次过程不能完全获得新门禁和新监测能力。
4. 源码版本仍为 2.3.1，同版本公开包不会包含此次修改，也不会触发更高版本更新。后续经用户要求发布时需要递增版本并重新构建、签名和验收。
5. 没有实际触发公开上传或生产安装，也没有验证真实断电、磁盘耗尽和全部硬件环境。
